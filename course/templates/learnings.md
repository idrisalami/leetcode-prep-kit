# Learnings

One entry per insight that came out of a problem: what happened, and the rule it gave you. **Newest entries go at the top of Entries**, straight under that heading, so the file reads from today backwards.

Language facts, such as how a slice copies or what `continue` does inside a nested loop, are learnings too. Tag them `[python]` after the date, so a search for `[python]` gives you your own Python reference.

Recurring bugs go in `bugs.md`, not here. A learning is an insight; a bug is a mistake you keep making.

## Entry template

Copy this block to the top of the entries and fill it in.

```
### <YYYY-MM-DD> — <the finding, in one line>

**What happened:** the problem (with its link), what you wrote, and what the review showed.

**The rule:** the sentence you apply next time.
```

A language fact looks the same, with the tag:

```
### <YYYY-MM-DD> [python] — <the fact, in one line>

**What happened:** where it came up.

**The rule:** the fact, stated so you can use it without running code.
```
